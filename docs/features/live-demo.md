# Feature: Live demo on GitHub Pages, with a showcase fixture and a Checkly monitor

## Status
In Progress

## Trigger
The human, 2026-11-28, for Day 20 ("Monitor your factory's output"):
- Deploy: "public demo on pages, you should make it look really nice, still have it interactable and things, make it quite well fleshed out to simulate the actual app, but also make it clear its a demo, so maybe you have to click play to play in the demo"
- Data: "invented fixture repo so we can show the entire variety of our app, with all different planet types and what they mean, a fake team of astronauts etc."
- Monitor: Checkly with email alerts.
- The lead may publish to Pages from a dedicated `gh-pages` branch after the privacy scan, the builder-security checklist and Qodo's review pass (human, 2026-11-28).

## Requirements
- [ ] L1 **Showcase fixture:** a deterministic, invented repo (no real people, paths or logs) whose scan covers:
  - every health band and planet look;
  - all three fog levels;
  - moons and moonlets;
  - a crew of 4–6 invented astronauts plus the captain;
  - several agent drones with panels;
  - co-change lines and a missing-pair flag;
  - beacons;
  - debris (stale branches) once R13 lands.

  Its output is the contract JSON every view route serves (`test/fixtures/contract/` style), generated by a script and committed.
- [ ] L2 **Demo build:** a static site, separate from `dist/web`, that runs the real view on the showcase data with no server.
  - Every read route is served from the baked files.
  - Writes (chart, beacon) work in memory for the visit only and are never sent anywhere.
  - No fetch to any other origin.
- [ ] L3 **Clearly a demo:** it opens on a title screen with the clearly labelled "DEMO" and a Play button; nothing animates until Play.
  - A small permanent "Demo: invented data" badge.
  - A short legend that explains what the planet types, fog, drones, crew and debris mean.
- [ ] L4 **Feels like the real app:** focus planets, open the review panel and chart a file (the fog clears), open drone and crew panels, use the directory view, Home. Same art and pixel pass.
- [ ] L5 **Privacy and security:** the visual-proof bundle scan (`privacyHits`) passes on the built site.
  - No tokens, no absolute paths, no third-party requests; a strict CSP that fits a static Pages site.
  - Verified by fetching the published URL anonymously.
- [ ] L6 **Published** on GitHub Pages from a `gh-pages` branch built by a script (main untouched). An anonymous load renders the title screen and, after Play, the system.
- [ ] L7 **Checkly check-as-code** in the repo, reviewed by Qodo.
  - A Playwright browser check opens the demo, presses Play, focuses a known planet, and asserts the info panel shows that planet's name and its file count from the fixture.
  - It also asserts the canvas isn't blank.
  - On a schedule, with email alerts. A separate temporary monitor with an unmet assertion proves the alert, then is removed.
- [ ] L8 **Tests:** the demo client's routes match the fixture files, in-memory writes never leave the page, and a render test proves the demo draws a non-empty frame after Play.

## Assumptions
- [x] The view already reads through a `DataClient` (`web/src/data/client.ts`), with a dev-only `fixtureClient` (`web/src/data/fixtures.ts`) over `test/fixtures/contract/`. A demo client can implement the same interface. (Verified by the lead, 2026-11-28.)
- [ ] Pages serves the repo at `/qodo-2026/`, so the demo build needs that base path.
- [ ] Checkly's free Hobby plan allows a scheduled browser check plus one temporary monitor, with email alerts (the human signs up; key in `~/.config/commet/checkly.env`, never in the repo).
