# Commet

> A local-first, pixel-art 3D explorer that helps a solo developer working with AI coding agents keep a real mental model of their own codebase. Entry for Qodo's "Build a Software Factory in 30 Days" hackathon (Nov 2 – Dec 2, 2026, solo).

**Read first:** `AGENTS.md` (house rules shared by every agent and by Qodo), `CONSTITUTION.md` (principles, autonomy, quality gates; approved), `docs/features/codebase-space-explorer.md` (requirements R1–R14, week plan), `JOURNAL.md` (state and decisions), `docs/design/art-direction.md` (the Current spec section is the visual source of truth).

## Stack (pinned at scaffold; see CONSTITUTION.md)
- TypeScript (strict), Node ≥ 20, npm.
- One `commet` npm package: scanner + CLI (native `git` via child_process, no language parsers) + terminal mode.
- One web bundle: Vite, three.js `WebGLRenderer`, GLSL. Served by `commet open` on a hardened 127.0.0.1 server (R14).
- Tests: Vitest (unit, golden, property), Playwright + SwiftShader for golden images.
- No remote servers, telemetry or uploads. GitHub API calls only as explicit read-only opt-ins.

## Build & Test
Node ≥ 20.19, npm. From the repo (or worktree) root:
- `npm ci`: install (lockfile-exact). In a new sandbox whose `package-lock.json` matches the session worktree's, clone instead: `cp -cR <session-worktree>/node_modules .` (seconds, no network, no extra disk on APFS).
- `npm run build`: `tsc` to `dist/` (the bin is `dist/cli.js`), then `vite build --config web/vite.config.ts` to `dist/web/` (the view `commet open` serves).
- The view's fog (#74): `view.fogTicket()` is taken before any request that returns fog, and `view.applyFog(fog, ticket)` is the single entry point (a stale ticket returns false; `View.load()` takes one too). Unknown or unusable fog draws everything fogged (Rule 1).
- `npx vite --config web/vite.config.ts`: the view's dev server on 127.0.0.1, with fixtures via `?fixture=mini|empty|invalid|missing`. Render test mode is `?test=1` (`window.__commet`).
- `npm run typecheck`: strict `tsc --noEmit` over `src/`, `test/` and `factory/`, plus `test/render` and `test/web/dom` with the DOM lib, and `web/`.
- `npm run lint`: ESLint. Bans `Math.random`, `Date.now`, `performance.now`, `crypto.randomUUID`, `new Date()` and `localeCompare` in `src/{core,scan,attrib}`, `web/src` and the render stand-in, Node built-ins in `src/core`, and U+0001 / `%x01` git-output framing in `src/{scan,attrib}` (AGENTS.md Rule 7).
- `npm run test:render`: Playwright + SwiftShader render tests (R8). A global setup builds `dist/web` first, so the specs always drive the current view. Goldens are authoritative only in CI's pinned container; locally the golden compare is informational (`test/render/README.md`).
- While working, run only the tests you touched (`npx vitest run <files>`), then typecheck and lint before you report. CI on the task PR is the full gate. Full local runs (no PR, or CI down) go through `lockf -k /tmp/commet-fullsuite.lock <cmd>`. See AGENTS.md Testing.
- `npm test`: Vitest (unit, golden, privacy canaries, lint rules). Test temp dirs only via `test/fixtures/tmp.ts` (`tempDir()`), cleaned per file and checked per run (#53). Golden snapshots live in `test/golden/`; regenerate only deliberately with `UPDATE_GOLDEN=1 npm test` and a `Golden-Update: <reason>` line in the commit.
- `node dist/cli.js scan [--window <months>] [--no-ingest] [--out <file>] [--root <dir>]... [--no-root] [--ask]`: run inside a clone. Writes `<git-common-dir>/commet/snapshot.json` and `layout.json` (`--out x.json` writes `x.json` plus `x.layout.json`). Exit codes: 0 ok, 1 internal, 2 usage, 3 shallow clone, 4 not a repo / no HEAD, 5 state error. `CLAUDE_CONFIG_DIR` overrides `~/.claude`.
- `node dist/cli.js open [--port <n>] [--no-open]`: serves the view, its layout, live fog and the drone view (`GET /api/drones`, #80: one entry per agent session with its home planet; an old snapshot without `Session.files` answers `needsRescan: true` and no homes, so rescan to place drones) and one session's own files and edit timeline for the drone panel (`GET /api/drone-detail?key=<session key>&at=<head>`, #148: 409 for another head, 404 for an unknown or inferred session; a snapshot from before #148 answers `needsRescan`), and accepts chart writes (`POST /api/chart`, recorded at the head the view saw, #58), on 127.0.0.1 only (R14, `docs/contracts/phase2.md`). It prints `http://127.0.0.1:<port>/#t=<token>` once and needs a snapshot first (exit 5 otherwise). `--no-open` keeps the token out of process lists. Exit 6: server bind failure.
  - While it runs it watches the served worktree's own HEAD plus `refs/heads`, `refs/remotes` and `packed-refs`, and runs one coalesced `commet scan` (argv only, no shell, never saves roots) after a commit, checkout, merge, rebase or fetch, so the view stays live without git hooks (#95). A failed rescan is printed in the terminal; the view gets only `{type: 'rescan', ok, exitCode}`.
  - The view also has a review panel (#75): `GET /api/unseen` and `GET /api/diff` (read-only, same gates) list and show a file's unseen diff; charting posts the viewed head as `at`.
- `node dist/cli.js hook install|remove [--yes] [--git-only|--claude-only]` (R7, #77): consent first; chains an existing git hook as `<hook>.commet-chained`; refuses a `core.hooksPath` outside the repo's git dir (this Mac's git-defender) and says what still works (`--claude-only`, manual `scan`). Records hashed edit events to `.git/commet/events.jsonl` (deduped; scan doesn't read it yet, #94). Exit 7 means not confirmed, nothing written. Every scan publishes its snapshot/layout pair under `publish.lock` (waits up to 5 s, else exit 5).
- `node dist/cli.js chart status | baseline [--undo] | [--note <text>] [--] <file>`: fog of war and chart state (R5); `--note` also leaves a beacon on the charted file (#79). Fog has three levels (#201, `fog.2`): fogged, haze (seen: charted, or its whole diff opened in the review panel) and clear (understood: a quiz passed on this version; a later content change re-hazes it); `status` prints each planet's files per level and its mastery % (clear ÷ files). Chart state lives in `<git-common-dir>/commet/chart.json` (`chart.2`: charts, quiz `clears` and baselines, ids and SHAs only, mode 0600; a `chart.1` file reads as charts only, all haze), with `chart.lock` as its write lock. Quiz passes are written only through `writeQuizPass` (#203), never a route or command. A bad path or a folder exits 2; damaged or symlinked state, or a snapshot and layout from different scans (#64), exits 5 and is never reset. `commet open` answers fog and chart requests over such a pair with a 500 carrying the same message.
- `node dist/cli.js beacon [list] | [--] <file> <note> | --remove [--] <file> | --remove-unplaced`: captain's log beacons (R10, #79). Notes live in `<git-common-dir>/commet/beacons.json` (file ids, SHAs and the note text only, mode 0600, `beacons.lock`), never in git notes. A note is 1–120 characters on one line, refused (exit 2), never rewritten, when it isn't. The view leaves one with a chart (the review panel's captain's log field) through `POST /api/beacon` and reads them at `GET /api/beacons`; the rule is `src/core/beacon-text.ts` (no package imports: the view and the render stand-ins load it), the shapes `src/core/beacons.ts` and `docs/contracts/phase2.md` "Beacons".
- `npm run factory -- labels|install|uninstall|tick [--once|--dry-run [--issue N]]`: the agent runner (`factory/`, built separately, not in the published package; see AGENTS.md "Agent runner"). The lead runs `install --interval 900 --base <current session branch>` itself (no human step) after any `factory/` change merges, and again whenever the session branch changes; see AGENTS.md "Agent runner". Runner state (lock, `ticks.jsonl`, `runs/`, the installed copy) lives in `<git-common-dir>/factory/`, never in the work tree.
- `npm run factory -- sweep [--dry-run] [--seed-through <PR>] [--max-calls <n>]`: the findings sweep by hand (`docs/features/repeat-findings.md`). Every tick also runs it: Qodo findings from the owner's PRs and local review exports go into a ledger in `<git-common-dir>/factory/findings/`, and a mistake seen 3 times across 2 tickets opens one `rule-proposal` issue for the human. `labels` creates the `rule-proposal` label.

The design mockups live on `feature/asset-library` (the art line) under `mockups/`: the asset viewer (the reference implementation), the asset library (the playground), and the drone, debris, health-looks and co-change labs (`mockups/cochange-lab/`, #211: `npm run dev` on 127.0.0.1:5195). Each folder is its own npm project (`npm ci && npm test` there; that branch's CLAUDE.md has the details). They are throwaway prototypes, not product code.

## Layout
- Drones (#80): `palette.drone.{generic,claude}` in `src/core/palette.ts` hold the drone ramps (BLK 36 only; the face screen and glow reuse `crew.visor`/`glint` and `accent.teal`). The drone art is `web/src/render/drone*.ts` (ported from the drone lab), the view logic `web/src/drones/`. At most 16 drones are drawn, the most recently ended placed sessions. A selected drone's panel (#148) lists the files that session edited at HEAD, grouped by folder with an edit count each (never sorted by count), one line for its edited paths not at HEAD, and a 24-slice pixel timeline of its edits; the counts come from the snapshot's `Session.fileEdits`, `editsOutside` and `editBuckets`. Inferred sessions get none (AGENTS.md Rule 6). The open panel docks in the corner that keeps its selected drone at least half visible over the drone's next turn (#189, `web/src/drones/dock.ts`, with hysteresis so it doesn't flicker); `test/render/drone-panel-sweep.probe.ts` (opt-in, `-c test/render/probe.config.ts`) still measures the old fixed bottom-left box.
- Co-change constellations (#211, R9): `commet scan` records `snapshot.cochange` (pairs by file id at HEAD with a Jaccard strength ×1000, at least 0.15 and 2 shared commits, each file's 5 strongest kept, commits over 200 files left out and counted; and the missing-pair flags: a strong partner, 0.50 over 3 or more shared commits, changed in the last 10 commits and the file didn't), `GET /api/cochange` serves them with the flags still standing (a chart or baseline at or after the raising change dismisses one) and the paths of the files they name (`docs/contracts/phase2.md` "Co-change"). The view (`web/src/cochange/`, ported from the co-change lab's option B) draws the focused planet's or the review panel's open file's lines into the internal target over the scene (`PixelPass.render`'s overlay), fitted around what the scene drew and every label, plus edge arrows and the always-visible teal flags, at most 3 flag texts in focus (art-direction §6 "Constellations").
- Directory view (#209, U10): the HUD's `files` toggle opens `web/src/tree/` beside the map, a WAI-ARIA tree of the snapshot's folders and files. Its paths come from the existing `GET /api/snapshot`, checked by `checkTreeSource`, which keeps only the head and each folder's and file's id and path; a list of another scan than the layout isn't shown. Files read fogged, haze or clear from the view's fog (`levelBy`, the source the map's shader reads). Folders show their mastery % with their haze and fogged counts, and a planet's own folder shows the planet's count, the info panel's (every file fogged without a usable fog view). Opening a row focuses its planet turned to its settlement or continent (`surfaceDirection`, `rig.focus(…, facing)`), or goes home to the star. A folder shows 200 rows at a time (`TREE_PAGE`), then an "N more" row that shows the next 200, so a big flat folder never builds every row at once.
- `snapshot.json` and `layout.json` produced by `commet scan`; local state in `.git/commet/` (snapshot, layout, `config.json` with the saved content roots, `chart.json` + `chart.lock`, `beacons.json` + `beacons.lock`, events).
- `layout(snapshot, history)` (`src/core/layout`) is a pure function. `history` comes from the full lineage replay, so layout.json can't be rebuilt from snapshot.json alone. Shape: `LayoutV1` in `src/core/contract/layout.ts`.
- Space mapping (#18): repo = star; top-level folders holding a non-test, non-test-data file = planets; second-level folders = continents; files = settlements; test files = moons of the planet they test; root files and unmatched tests = moonlets; test data is counted on the star, never drawn.
- Content roots (#71): the first `scan` in a terminal guesses the main code folder (e.g. `src`) and asks to confirm; the answer is saved in `config.json`. Each root's subfolders become content planets (slots 0–7); other top-level folders are outer planets (from slot 9). Files directly in a root are star moonlets. Without a TTY, the scan uses the saved answer, else the last layout's roots (#73), else the guess, and never asks or saves. `--root`, `--no-root` and `--ask` override; with `--out` they apply to that scan only and nothing is saved (#115).

## Rules
- Read files before editing. Don't guess what exists.
- No features beyond the task. Match existing patterns; don't refactor adjacent code.
- **Determinism:** no `Math.random` in pipeline, layout or render code; use the pinned seeded PRNG and hash. No wall-clock time in snapshots.
- **Privacy:** never copy code, prompt text or absolute paths from agent logs into any output. Never read `originalFile`, `last-prompt`, `history.jsonl`, `file-history/`, `api-request*` or `attachment` records (see `docs/research/agent-attribution.md`).
- **Golden and property tests** are updated deliberately with a reason, never regenerated just to pass. Render tests must fail on empty output.
- Test what you change as you go; CI runs the full gate on the PR. Fix what you break.
- **Stage explicit paths only.** Never `git add -A` or `git add .`; other sessions write files in this checkout.
- New dependencies need a one-line justification in the PR description.

## Branching
- `main` changes only with the human's approval. Never merge into or push `main`.
- Work happens on `session/<name>` branches; feature agents use `feature/<name>`, debuggers `debug/<name>`, each in a worktree under `.sandboxes/`.
- Integrate by rebase + fast-forward. The team lead merges; other agents only commit on their own branch.
- Commits: conventional style (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), small and focused.

## Gotchas
- `JOURNAL.md` and `.archive/` are gitignored and absent from worktrees. Reference them by absolute path, e.g. `<main-checkout>/JOURNAL.md` and `<main-checkout>/.archive/...`, where `<main-checkout>` is `$(git rev-parse --path-format=absolute --git-common-dir)/..`.
- Qodo can't see binary files. Report visual results as text (test output, colour counts) in PRs.
- `refs/notes/commet` is reserved for attribution events, not user notes.
- A temp clone gets 0 drones from `commet scan`: agent logs match a repo by its git common dir, and a clone has its own. For drone footage, scan a worktree of the real repo read-only (Day 7 GIF, `day7-scratch/gif-tools/scan-real.mjs` in the archive).

## Context management
- When context feels long (50+ tool calls, or responses getting shorter): write your current plan to PLAN.md, then run `/compact`.
- Compact after finishing research, a bug fix or a feature, not during active implementation or debugging.

## Agent auto-routing
- Before you report a finished task: typecheck, lint and the touched tests (no `/verify` after every edit, no `/simplify` sweeps).
- When a build or test fails: run `/fix` with the error output.
- Before committing: review `git diff --cached` for debug code, secrets and stray files.
- Before a fix PR: `/fix-proof <fix commit> <tests>` (`.claude/skills/fix-proof`): proves each test fails without the fix.
- Before a view-change PR: `/visual-proof <base> <head|--worktree> <scene>` (`.claude/skills/visual-proof`): films the change before and after from the same data, checks the takes match and scans for private data; paste its `summary.md` into the PR, and the human attaches the images.
- When exploring unfamiliar code: use the `explorer` agent.
